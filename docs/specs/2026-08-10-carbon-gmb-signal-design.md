# Carbon-Signal / Green-Minus-Brown Research — Design

**Date:** 2026-08-10
**Status:** Approved (full pivot)

## 1. Motivation

The repository previously shipped a climate-finance *flows* dashboard (OECD / World
Bank / IRENA). Every input was synthetic — generated by `numpy.random` with a
hardcoded 12% growth trend — while the README and GitHub description implied real
data. Two problems:

1. **The central claim was false.** The first question asked of any data project is
   "where is the data from?"
2. **Wrong domain for the target audience.** Climate-finance flows are annual,
   aggregate, non-tradeable development-economics series. No amount of rigor makes
   that read as quantitative research.

This project is repurposed into a reproducible quant research study on **real market
data**, keeping the climate theme.

## 2. Research question

> Does the price of carbon allowances predict the relative performance of green
> equities versus brown (fossil-fuel) equities?

Economic intuition: a rising carbon price raises the cost of emitting. That is a
headwind for carbon-intensive producers and a tailwind for clean-energy substitutes.
If markets price this with a lag, carbon-price momentum should forecast the
green-minus-brown spread.

**Success is a correct, honest answer — not a profitable one.** A well-executed
null result is a legitimate outcome and is reported as such. Overfitting an
attractive equity curve is the failure mode to avoid.

## 3. Data

Daily adjusted closes from Yahoo Finance (`yfinance`), cached locally to CSV so runs
are reproducible offline.

| Role | Tickers |
|---|---|
| Green basket | ICLN, TAN, PBW |
| Brown basket | XLE, XOP |
| Carbon proxy | KRBN (KraneShares Global Carbon Strategy) |
| Benchmark | SPY |

**Known limitation, stated up front:** KRBN's inception is 2020-07-31, so the
carbon-signal test runs on roughly five years of daily observations (~1,300 points).
This is a small sample for a strategy claim and is reported alongside every result.
The green-minus-brown factor itself is characterised over its own longer history.

### TLS note (environment-specific)
This machine performs TLS interception, so HTTPS fails with default CA bundles.
`truststore` fixes Python's `ssl` module but **not** `curl_cffi`, which `yfinance`
uses. Ingestion therefore builds a combined CA bundle (certifi + Windows cert store)
and points `CURL_CA_BUNDLE` at it. Cached data means this only matters on refresh.

## 4. Method

1. **Factor construction.** Equal-weighted green basket minus equal-weighted brown
   basket, daily rebalanced, using simple returns:
   `GMB_t = mean(green returns) - mean(brown returns)`.
   Characterise: annualised return, volatility, Sharpe, max drawdown, and
   correlation/beta to SPY (is this a distinct factor or repackaged market beta?).

2. **Hypothesis test.** Regress forward GMB returns on carbon momentum. Report the
   coefficient, **Newey–West** t-statistic (daily overlapping returns are
   autocorrelated; OLS standard errors would overstate significance) and R².

3. **Signal.** One rule, deliberately simple:
   `carbon_momentum_t = trailing 60-day return of KRBN`, position = sign of that
   momentum, scaled to a 10% annualised volatility target using *trailing* realised
   GMB volatility, with a leverage cap.

4. **Backtest.** Position formed at close of day *t* is applied to the day *t+1*
   return. Transaction costs charged on turnover; the spread trades two legs, so
   cost = turnover x bps x 2. Metrics: annualised return, volatility, Sharpe, max
   drawdown, hit rate, turnover — reported **in-sample and out-of-sample
   separately**, benchmarked against buy-and-hold GMB.

5. **Robustness.** Sensitivity sweep across lookback windows and cost assumptions,
   reported as a distribution rather than a single cherry-picked configuration.

## 5. Correctness guardrails

These are the substance of the project, not decoration:

- **No lookahead.** Signal at *t* uses only data up to *t* and is applied to *t+1*
  returns. Enforced by an explicit shift and covered by a unit test that corrupts
  future data and asserts backtest results are unchanged.
- **Out-of-sample separation.** A fixed chronological split; OOS metrics are the
  headline figures.
- **Costs and turnover always reported**, never a gross-return-only result.
- **Deterministic and reproducible.** Cached inputs, pinned dependencies, one
  command reruns end to end.

## 6. Architecture

```
etl/ingest.py      fetch + cache daily prices (yfinance, TLS-aware, retries)
etl/clean.py       calendar alignment, returns, missing-data policy
etl/aggregate.py   baskets, GMB factor, carbon features -> panel
research/stats.py  performance metrics, Newey-West regression
research/signal.py signal construction (causal by design)
research/backtest.py  position -> P&L with costs, IS/OOS, sensitivity
research/report.py    orchestration -> results JSON
dashboard/app.py   Dash presentation layer
tests/             returns math, P&L accounting, no-lookahead
```

## 7. Removed

`generate_sample_data.py` and all synthetic CSVs are deleted. The README and GitHub
description are rewritten to describe exactly what the project does. No claim
survives that the code does not support.
